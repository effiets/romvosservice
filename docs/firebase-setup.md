# Ρύθμιση σύνδεσης ομάδας ROMVOS

Το Email/Password έχει ενεργοποιηθεί στο project `romvos-service` και έχει δημιουργηθεί ο πρώτος χρήστης. Μην κοινοποιείς κωδικούς. Κάθε μέλος θα έχει δικό του λογαριασμό.

## 1. Δημιουργία βάσης

Στο [Firebase Console](https://console.firebase.google.com/project/romvos-service/overview), άνοιξε **Firestore Database → Create database**.

- Επίλεξε **Standard edition** και το προεπιλεγμένο database ID `(default)`.
- Επίλεξε ευρωπαϊκή τοποθεσία κατάλληλη για την ομάδα. Η τοποθεσία δεν αλλάζει μετά τη δημιουργία της βάσης.
- Ξεκίνα με **Production mode** (κλειστή πρόσβαση).
- Για αυτή τη φάση δεν απαιτείται ενεργοποίηση πληρωμών, Functions ή Storage.

## 2. Κανόνες πρόσβασης

Άνοιξε **Firestore Database → Rules**, αντικατάστησε τους αρχικούς κανόνες με το πλήρες περιεχόμενο του αρχείου `firestore.rules` αυτού του repository και πάτησε **Publish**.

Εναλλακτικά, αν χρησιμοποιείς ήδη το Firebase CLI:

```sh
firebase deploy --only firestore:rules --project romvos-service
```

Το GitHub workflow δημοσιεύει μόνο Hosting. Δεν δημοσιεύει τους κανόνες της βάσης.

Οι κανόνες επιτρέπουν στον συνδεδεμένο χρήστη να διαβάζει τη δική του εγγραφή μέλους. Η ενημερωμένη έκδοση επιτρέπει επίσης κοινό προγραμματισμό σε ενεργά μέλη: owner/editor αποθηκεύουν και viewer διαβάζει. Ο διαχειριστής του Firebase project προσθέτει μέλη από το Console· οι χρήστες της εφαρμογής δεν μπορούν να αλλάξουν τη συμμετοχή τους.

## 3. Πρώτο εγκεκριμένο μέλος

Στο **Firestore Database → Data** δημιούργησε την παρακάτω διαδρομή. Χρησιμοποίησε το πραγματικό **User UID** από Authentication → Users ως τελικό document ID, όχι το email και όχι αυτόματα παραγόμενο ID.

```text
workspaces / romvos / members / USER_UID
```

Αν το Console ζητήσει πεδίο για το ενδιάμεσο document `romvos`, πρόσθεσε `name` (string) = `ROMVOS Service`.

Στο τελικό document `USER_UID` πρόσθεσε:

| Πεδίο | Τύπος | Τιμή |
|---|---|---|
| `active` | boolean | `true` |
| `role` | string | `owner` |

Για επόμενα μέλη, χρησιμοποίησε αντίστοιχα UID και role `editor` ή `viewer`. Η διάκριση δικαιωμάτων εφαρμόζεται στην κοινή αποθήκευση προγραμματισμού. Οι ενότητες που δεν έχουν μεταφερθεί ακόμη παραμένουν τοπικές.

## 4. Δοκιμή

```sh
npm test
npm run build
python3 -m http.server 8877 --bind 127.0.0.1 --directory yes
```

Άνοιξε `http://127.0.0.1:8877`, πάτησε **Σύνδεση χρήστη** και βάλε τα στοιχεία του λογαριασμού σου. Η δοκιμή απαιτεί σύνδεση στο διαδίκτυο, ακόμη και στον τοπικό server.

- Με σωστά στοιχεία και ενεργό μέλος πρέπει να εμφανιστεί επιβεβαίωση πρόσβασης στην ομάδα.
- Με λανθασμένο κωδικό πρέπει να εμφανιστεί μήνυμα αποτυχίας.
- Με χρήστη χωρίς εγγραφή μέλους πρέπει να εμφανιστεί μήνυμα μη ενεργής πρόσβασης.
- Η φόρμα δεν επιτρέπει δημόσια δημιουργία λογαριασμών ούτε προσθήκη μελών.

Η σύνδεση χρήστη από μόνη της δεν στέλνει τις υπάρχουσες εργασίες ή επαφές στο Firebase. Η κοινή λειτουργία ενεργοποιείται ξεχωριστά από το **Κοινό πρόγραμμα**. Ο κωδικός δίνεται μόνο στο Firebase Authentication. Η συνεδρία διατηρείται για τη διάρκεια της καρτέλας και δεν συμπεριλαμβάνεται στο JSON backup της εφαρμογής.

## 5. Υποχρεωτική σύνδεση — μετά τη δοκιμή

Στο `assets/js/auth-config.mjs` η ρύθμιση `requireSignIn` παραμένει `false` για να μην κλειδωθεί η εφαρμογή πριν ολοκληρωθεί η ρύθμιση. Μόνο μετά από επιτυχή δοκιμή εγκεκριμένου λογαριασμού μπορεί να γίνει `true`, να ξανατρέξει το build και να δημοσιευτεί η εφαρμογή.

Η ρύθμιση αυτή ελέγχει τη διεπαφή. Τα cloud δεδομένα προστατεύονται από τους κανόνες του Firestore ανεξάρτητα από το JavaScript του browser. Τα τοπικά δεδομένα παραμένουν κοινά στους χρήστες του ίδιου browser· η σύνδεση σε αυτή τη φάση δεν τα απομονώνει ανά λογαριασμό και δεν προσθέτει κοινή αποθήκευση ή live updates.

Για την ενεργοποίηση και τη δοκιμή της κοινής αποθήκευσης, διάβασε το [Κοινό πρόγραμμα](shared-scheduling.md). Τα τελικά πλήρη JSON backups και η δοκιμή επαναφοράς ακολουθούν πριν από την ολοκλήρωση της μετάβασης όλων των ενοτήτων.
